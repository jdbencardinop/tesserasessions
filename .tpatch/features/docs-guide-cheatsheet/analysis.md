# Analysis: docs-guide-cheatsheet

## Summary

Add first-party documentation for the new `tss` CLI so the project is usable without reading source code. The documentation should cover install/development usage, command examples, data/config locations, safety/privacy defaults, current limitations, and the newly adopted tpatch workflow.

## Compatibility

- Compatible with the current Go/Cobra CLI in `cmd/tss` and `internal/cli/root.go`.
- No runtime behavior change is required.
- Documentation must reflect the currently implemented commands, not future-only commands.
- tpatch state lives in `.tpatch/` and should be referenced as the roadmap source of truth.

## Affected areas

- `README.md`
- `docs/cheatsheet.md`
- `docs/roadmap.md`
- `.tpatch/FEATURES.md` and `.tpatch/features/*` generated by feature registration

## Risks

- Docs can drift if command flags change.
- The project is not a git repository yet, so full tpatch record/land workflows may be limited until git history exists.
- Herdr is optional and not installed on this machine, so docs should describe it as preferred when available, not guaranteed.
