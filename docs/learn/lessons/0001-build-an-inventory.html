TimeAbout 8 minutes.

A scan updates a projection

The source tool owns its historical store. tss scan reads supported metadata and writes a normalized local inventory. It never makes the inventory more authoritative than the evidence it received.

Local inventory write Source stores remain read-only, but scan does mutate the local tss inventory.

Practice: classify each provider report

  1. Check configured paths and optional tools: 
    tss doctor
  2. Ask for structured scan reports: 
    tss scan --json
  3. Read this synthetic result: 
    [
  {
    "source": "claude",
    "sessions": 4,
    "runtimes": 0,
    "skipped": false
  },
  {
    "source": "codex",
    "sessions": 2,
    "runtimes": 0,
    "skipped": false,
    "message": "Codex scan incomplete: skipped 1 unreadable rollout"
  },
  {
    "source": "herdr",
    "sessions": 0,
    "runtimes": 0,
    "skipped": true,
    "message": "Herdr is unavailable"
  }
]
Source Decision
Claude Complete result; its source snapshot can reconcile.
Codex Valid rows refresh, but prior Codex rows are not pruned.
Herdr Optional live provider skipped; historical scans can still succeed.

Retrieve the rule

A Codex scan returns two valid sessions and one unreadable active rollout. What happens?

Reveal answer and reasoning

Answer B. An incomplete snapshot can upsert valid sessions, but it cannot prove that absent rows disappeared upstream.

Checkpoint

You are ready for lesson 2 when you can explain why "skipped" is not automatically an error and why "incomplete" disables pruning.
