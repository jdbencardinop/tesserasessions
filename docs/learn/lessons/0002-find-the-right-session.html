IDs and paths in this lesson are synthetic. Replace codex-demo123 with an ID returned by your own tss list.

Start broad, then add evidence

Session IDs are source-qualified. Project path, source, title, tags, status, and recency help select the intended record without opening transcript content. 

tss list --limit 20
tss list --source codex --query demo-api --sort last
tss list --status needs_attention --tag review
tss search demo-api --source claude

Metadata only These searches use normalized metadata and summaries.

Inspect before action

tss show codex-demo123

Check the fields that answer different questions:

Field Question answered
Source and native ID Which tool owns the resume identity?
Project path Which checkout or worktree does it belong to?
Last activity Which candidate is most recent?
Status, title, tags, pin What local operator context has been recorded?
Resume/attach commands What return paths are available?

Content search is a separate choice

Explicit content access tss search demo-api --content lazily reads supported transcript/content snippets. Do not add --content merely to improve a metadata query.

Choose the least-invasive query

You know the source is Codex and the project contains "demo-api." Which command should you try first?

Reveal answer and reasoning

Answer A. It combines known metadata evidence. Content access is unnecessary, and show requires one session reference.

Checkpoint

You are ready for lesson 3 when you can find one source-qualified record and explain why its project path is evidence, not identity.
