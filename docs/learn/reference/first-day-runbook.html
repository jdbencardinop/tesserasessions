1. Know which layer you are looking at

Layer Evidence How it changes
Source store Agent-owned historical metadata and native resume identity. The source tool owns it; tss reads it.
Inventory Local normalized sessions in the tss database. An explicit tss scan refreshes it.
Runtime Live Herdr/tmux observations with freshness. tss status --json probes in memory.
Control Attach, resume, open, send, read, or run commands. Preview with --print; execute deliberately.

2. Run the safe daily sequence

  1. Check discovery and configuration. Read/health check 
    tss doctor
    Confirm the expected source paths exist. A missing optional backend is not the same as a broken historical source.
  2. Refresh the local inventory. Local inventory write 
    tss scan --json
    Source stores remain read-only. Inspect every report for skipped, message, or error.
  3. Narrow by metadata. Metadata only 
    tss list --limit 20
tss list --source codex --query demo-api --sort last
tss search demo-api --source claude
    Do not add --content unless transcript/content access is intentional.
  4. Inspect one exact session. Metadata only 
    tss show <session-id>
    Verify source, native ID, project path, timestamps, status, and the available resume/attach commands.
  5. Preview the return path. Interactive when executed 
    tss attach <session-id> --print
    Read the generated command. Remove --print only when the target and action are correct.

3. Interpret scan reports

Report Meaning Operator action
Sessions/runtimes counted, no message The source scan completed. Continue to list and inspect.
skipped: true The optional store/provider was unavailable. Check doctor; ignore it if intentionally absent.
Incomplete warning Valid rows refreshed, but not every authoritative item was readable. Prior rows were preserved; retry after the source settles.
error The source could not provide a usable scan. Fix the source/path/schema issue; do not edit databases manually.

4. Choose attach, resume, or open

A matching live runtime exists

Use tss attach <id> --print. It prefers the live backend and shows the exact attach command.

No matching runtime, but the historical session is resumable

Use the same attach preview. tss falls back to the source-qualified native resume command.

You want a new environment, not the old conversation

Use tss open <id> --print. This opens Herdr/tmux in the project directory; it does not resume conversation history.

5. Diagnose live state without scanning

Side-effect-free status --json does not open the inventory, scan sources, attach, focus, or send input. 

printf '%s\n' '{
  "schema_version": 1,
  "queries": [{
    "query_id": "demo-api",
    "path": "/workspaces/demo-api",
    "repo_root": "/repos/demo",
    "git_branch": "feature/demo"
  }]
}' | tss status --json
Runtime presence Agent state Interpretation
present working A matching live agent is doing work.
present ready A matching live agent can accept input.
present blocked Live evidence exists and needs attention.
absent unknown No matching live runtime was observed.
stale unknown Evidence exists but is outside its freshness window.
unknown unknown Provider coverage or match evidence is insufficient.

6. Leave the next handoff cleaner

tss summarize <session-id>
tss title <session-id> "Finish demo API migration"
tss tag <session-id> demo,review
tss pin <session-id>
tss mark <session-id> needs_attention

Manual titles, tags, and pins survive scans for sessions that still exist. A manual mark is transient: a later scan can replace status with the source-derived value.

7. Troubleshooting decisions

Symptom Check Do not
Expected source is skipped tss doctor, environment override, configured path. Create fake source files.
Scan is incomplete Retry after active writes settle; inspect the warning path. Delete prior inventory rows.
Session reference is not found Rescan, then use list or search. Guess a native ID.
Attach target looks wrong show, then compare attach --print. Execute before reviewing.
Live status is unknown Provider availability, errors, path, repository, branch. Treat unknown as absent.
Need transcript text Use search --content only with explicit intent. Assume metadata search reads content.

Privacy checkpoint

  • Never commit the inventory database or source stores.
  • Redact IDs, paths, repositories, and output before filing issues.
  • Prefer metadata-only commands; content search is opt-in.
  • Review generated control commands before execution.
  • Do not edit source stores or SQLite to repair scan behavior.
